1 The programme behind these dashboards

Every dashboard on this page is a slice of one hypothetical delivery. Imagining a single, end-to-end programme is what forces each metric to earn its place — because an unanswered question somewhere else is a defect waiting to be shipped.

Business situation

Legacy state. A regional bank runs its core payments ledger on a 22-year-old COBOL + Oracle system. Operations run cases from an in-house ticketing tool. Settlement is batch, overnight; reconciliation to the central bank is partially manual. Regulator has flagged the reconciliation window as a systemic risk and set a 12-month deadline.

Target state. A cloud-native payments platform (Java + Postgres + Kafka) speaking ISO 20022, with Salesforce Service Cloud as the agent desktop for operations. Settlement moves from batch to near-real-time with intra-day reconciliation. AI augments triage, data validation and release decisions — as explicit, auditable agents, not black-box automation.

Why now. Regulatory deadline, 25% cost base locked in legacy mainframe licensing, and no vendor-side defect fix path for the current switch.

Banking core ISO 20022 Salesforce Service Cloud Data migration Legacy COBOL/Oracle Regulatory reconciliation AI QE pod

Why this makes a good dashboard case study

A banking modernization touches every surface a Senior Test Manager owns in a steering review: data integrity (migration + reconciliation), functional risk (payment correctness, rollback), operational risk (Salesforce case flow + agent desktop), release risk (pilot → GA ramp) and programme risk (velocity, defect aging, environment health). The same twelve dashboards you need here are the twelve you need on any modernization — so building them against this story keeps them honest.

4 Testing types needed across the programme

What the 3 QA + 1 SDET Lead actually run, mapped to the dashboards that will show the evidence. "Done" isn’t a test type — it’s a dashboard reading "green for N consecutive sprints".

DMData migration validation

Source profiling, record-count reconciliation per table, field-level diff on primary + risk columns, transformation-rule assertions.

  • Row count exact; business-key uniqueness
  • Checksum per risk column (amount, BIC, status)
  • Null-ratio drift < 0.5%

RCReconciliation (end-to-end + intra-day)

Net-position reconciliation between core ledger, payment switch and central-bank sandbox; signed CSV; tolerance 0.01%.

  • Hourly intra-day job; T+0 close
  • Variance > tolerance opens a case automatically
  • AI diff narrator explains the mismatch

RBRollback / DR drills

Point-in-time restore of Postgres ledger, cross-check against legacy Oracle snapshot, dual-run cutback runbook.

  • Scheduled drill at Sprint Demo240
  • Rollback RTO < 2h; RPO < 15 min
  • Automated reconciliation check post-restore

FCFunctional & contract

ISO 20022 schema contract tests; Salesforce case-flow BDD; payment correctness including reject paths.

  • Contract tests gate every PR
  • End-to-end payment: happy, reject, timeout, duplicate
  • Case SLA assertions on routing

PFPerformance & chaos

Baseline at 1x expected volume Sprint Demo237, 3x by Demo243; chaos: broker loss, dead-letter spike, DB failover.

  • p95 latency < 600ms at 3x
  • No message loss on broker loss
  • Automatic failover within 30s

SESecurity & compliance

Threat model refresh; SAST/DAST in CI; audit of PII on new paths; penetration test pre-pilot.

  • Zero critical SAST findings on main
  • Pen test closed before Sprint Demo242
  • Audit trail for every reconciliation decision

PRPilot release (canary)

Feature-flagged ramp 5% → 25% → 50% → 100% over Sprint Demo242; auto-rollback on error-budget burn.

  • Error budget: 0.3% of pilot volume
  • Cohort selection excluded high-value accounts in week 1
  • Rollback trigger wired to Pilot Rollout dashboard

FBFeedback loop

Pilot survey weekly, NPS from agents (Salesforce desktop), operations stand-up readout; telemetry on top-5 agent flows.

  • Agent NPS > 30 by end of pilot
  • Top-5 case-resolution time ≤ legacy
  • All open feedback items triaged within 48h

How "reconciliation" and "rollback" actually surface to the steering committee

Reconciliation. The intra-day job writes a signed CSV. The Reconciliation dashboard shows net position by rail, variance against tolerance, and the top-5 unresolved mismatches with the AI diff narrator’s explanation attached. Steering sees one number — "variance within tolerance for 14 consecutive runs" — not the CSV.

Rollback. We don’t promise a flawless cutover; we promise a credible cutback. The Pilot Rollout dashboard shows the rollback RTO/RPO measured in the Sprint Demo240 drill, the time it took, which runbook step was slowest, and the owner for the next drill. Steering sees "drill completed within RTO, 1 action" — and asks about the one action.

Pilot & feedback. Pilot ramp percent, error-budget burn, agent NPS and the top-5 feedback themes are the same card, so there’s no "green on numbers, red on sentiment" blind spot.

5 Where AI shows up across the programme

Six AI agents, each with a clear job, a human in the loop, and a dashboard they report to. "AI in QE" without a dashboard is a demo; with one, it’s a decision.

Triage agent QE-02

Clusters pipeline failures by stack-trace signature; proposes flake / env / real defect with cited evidence; a human approves before close.

Dashboards: Governance, Defect Analytics, Automation Effort.

Risk-based test selection QE-06

Given a diff + 90-day defect history, proposes a <30-min smoke set with a coverage justification. Full suite still runs nightly.

Dashboards: Automation Effort, ROI, Governance.

Reconciliation diff narrator PR

Takes a numeric variance from the reconciliation job and produces a 3-line explanation with pointers to the responsible payment IDs and rules.

Dashboards: Reconciliation, Risk Register.

Synthetic data generator DM/PR

Generates edge-case payments (currency corner cases, reject codes, out-of-order message pairs) with provenance for every row.

Dashboards: Automation Effort, Defect Analytics.

Log clustering + RCA draft XC

Clusters application logs across the message path; drafts a root-cause narrative for the on-call to confirm.

Dashboards: Defect Analytics, Pilot Rollout.

Test case drafter PLN

Reads a BRD / user story, drafts Gherkin scenarios with acceptance criteria and risk notes; QA edits before accepting.

Dashboards: Test Strategy, Test Plan.

7 What’s inside each dashboard

For the tiles that don’t yet have a live sample page, this is the field-level specification — the one question it answers, the KPIs it tracks, and where AI plugs in.

🎯 Test Strategy

Answers: How are we testing this programme, and why?

The strategy card has one tab per layer (unit, API/contract, UI, data, perf, security, chaos) with a per-sprint entry/exit, tool, environment and owner. The acceptance gates (functional, data integrity, performance, operational readiness) are visible with target thresholds, not vague adjectives.

  • Coverage by layerTarget vs actual coverage %, trend over 4 sprints.
  • Test type mix% unit / contract / E2E / manual; alarm if E2E > 25%.
  • Environment uptimeStaging + regulator sandbox uptime, data refresh SLA.
  • Gate stateEntry/exit per gate, who’s the sign-off.
🤖 AI: the test-case drafter proposes scenarios from BRDs; QA accepts, edits or rejects with a reason that feeds back into the agent’s eval set.

💵 ROI Calculator

Answers: What did QE automation save this programme?

Open formulas, not black boxes. Each metric shows "(cost today) vs (cost without the automation / without the AI agent)" using sprint-level data. The AI pod has its own cost line — the ROI number is net of agent spend.

  • Manual-hours avoidedPer sprint, split by automation vs AI pod.
  • Cycle-time deltaPre-release regression hours; before / now / target.
  • Pre-prod catch rateDefects caught before UAT / before prod.
  • $ / defect avertedWith formula and the inputs visible.
  • Payback periodFor AI pod cost; break-even sprint.
🤖 AI: risk-based test selection shaves ~40% off gate-time without losing coverage — the dashboard reconciles the two numbers so steering doesn’t have to.

🤖 Automation Effort

Answers: Where is automation effort landing, and is it paying off?

Keeps the team honest about new vs maintenance. A sprint where 70%+ of QA time went to maintenance is a flag, not a surprise.

  • New vs maintenance %Per sprint, per QA.
  • Flake rateTarget < 1.5%; shown by suite.
  • MTTR for broken testsMedian + p90.
  • Pass-rate stabilityRolling 10-run pass rate.
  • Suite runtimeFull suite + risk-based smoke subset.
🤖 AI: the triage agent reclassifies failures as flake vs real-defect vs environment, feeding the flake-rate number automatically.

🛡 Release Readiness (Go / No-Go)

Answers: Can we ship? What’s open?

Four cards — Functional, Data, Performance, Operations — each with a RAG, an owner, a cite-your-evidence link, and a "what would make this red" sentence. Updated T-2 days before every steering committee.

  • Gate RAGFunctional / Data / Perf / Ops.
  • Open P1/P2With age bucket and owner.
  • Rollback drill freshness< 1 sprint old at pilot.
  • Pilot error-budget burnOnly visible during Sprint Demo242.
  • DependenciesExternal sign-offs waiting (regulator, vendor).
🤖 AI: log clustering surfaces "this incident looks like class X we closed in Sprint Demo239" so the gate conversation is grounded.

🐞 Defect Analytics

Answers: Where do defects come from, and where are they stuck?

  • Aging matrixSeverity × age-bucket; targets per bucket.
  • Injection vs detection phaseShift-left evidence.
  • Defect densityBy module; outliers highlighted.
  • Reopen %Rolling 4-sprint.
  • DREDefect Removal Effectiveness per phase.
  • Top-5 themesClustered from defect bodies by the triage agent.
🤖 AI: clustering produces the top-5 themes; log-RCA agent attaches a candidate root cause to each new P1.

⚠ Risk Register

Answers: What could stop us, and who owns it?

  • Top-15 risksProbability × impact (1-5 each), owner, mitigation.
  • Mitigation freshnessDays since last update; flag > 14.
  • Stale-risk flagRisks unchanged in 3+ steering reviews.
  • Realized risksRisks that became incidents, with before/after cost.
🤖 AI: the diff narrator from the reconciliation job writes an auto-draft risk whenever variance breaches tolerance — a human owner confirms it before it lands on the register.

📊 Reconciliation Dashboard

Answers: Did the right data land, and does it still balance?

  • Row-count deltaPer table source → target per batch.
  • Field-level diff %On risk columns (amount, BIC, status, dates).
  • Variance vs toleranceNet position per rail per hour (tolerance 0.01%).
  • Time to resolve mismatchMedian + worst-case.
  • Signed-pack freshnessLast signed CSV to regulator sandbox.
🤖 AI: the diff narrator reads a variance and produces a 3-line explanation, with linked payment IDs and rule references. Humans decide, but on signal, not noise.

🚀 Pilot Rollout

Answers: How is the canary going, and can we roll back?

  • Ramp %5 / 25 / 50 / 100 cohort state.
  • Error-budget burnBudget 0.3% of pilot volume.
  • Cohort compositionBy segment; high-value accounts excluded week 1.
  • Agent NPSWeekly; target > 30.
  • Rollback RTO / RPOFrom last drill; target 2h / 15min.
  • Open feedback themesTop-5 with owner + due sprint.
🤖 AI: log cluster + RCA agent for pilot incidents, always with human sign-off before customer comms.
